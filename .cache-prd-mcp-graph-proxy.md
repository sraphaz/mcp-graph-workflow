# Plano: Embed **MCP-Graph Proxy** na mcp-graph v12.x

## Contexto

Nome oficial do componente: **MCP-Graph Proxy**. Inspiração direta: a extensão "LM Proxy" do VS Code que o usuário já usa hoje para conectar `browser-use` e o GitHub Copilot a APIs OpenAI-compatible — ou seja, **expõe um endpoint HTTP local OpenAI-compatible** que clientes externos consomem via `OPENAI_API_BASE`. O MCP-Graph Proxy precisa ser equivalente, mas integrado ao daemon do mcp-graph (graph.db, ledger de custo, telemetria, budget guard).

A v12.0.0 de `mcp-graph-workflow` (top-level `package.json`) **NÃO** tem nada disso. O que existe hoje:

- `src/core/browser-harness/llm-client.ts` — cliente estreito (Anthropic Messages + GitHub Copilot apenas), usado **somente** pelo self-heal do browser-harness (`LlmPlanner`).
- `tools/h9v2-pilot/openrouter-client.ts` — pilot solto (não integrado ao src/), legado dos experimentos H9v2.
- `src/mcp/stdio-proxy.ts` — bridge de transporte MCP (stdio↔socket). **Não confundir**: não roteia LLMs.
- Demais tools (`delegate`, `analyze`, `context/rag`, `dream`, `siebel`, `davinci`) hoje delegam ao Claude Code pai — não há gateway centralizado.

**Por que fazer agora (driver primário)**: **sem o MCP-Graph Proxy o mcp-graph não consegue conectar ao browser-use-harness para testes autônomos de frontend**. O browser-use precisa de um endpoint OpenAI-compatible local; hoje o usuário depende da extensão LM Proxy externa, fora do controle do graph (sem ledger, sem budget guard, sem rastreabilidade por cell/run). Internalizar como MCP-Graph Proxy é pré-requisito do loop autônomo de E2E frontend. Drivers secundários: (a) experimentos H12+ (eva-agent) com OpenRouter precisam ledger persistido; (b) substituir LM Proxy externo no Copilot/Continue com mesma UX; (c) impor a regra "<$1/cell, sem claude-sonnet/opus nem gpt-4o/5" em todo tráfego.

**Escopo combinado** (escolhido pelo usuário, refinado pelo print + uso com browser-use-harness):
1. **Gateway-SDK interno** (`LlmGateway`) consumido por browser-harness, MCP tools e runners.
2. **Servidor HTTP OpenAI-compatible** ("MCP-Graph Proxy" propriamente dito) — endpoint `/v1/chat/completions`, `/v1/models` — **alvo primário: browser-use-harness para E2E autônomo de frontend**; alvos secundários: GitHub Copilot, Continue, Cline. Todos apontam `OPENAI_API_BASE=http://127.0.0.1:PORT/v1` e ganham ledger + budget guard automáticos, com `caller` rastreado por header.
3. **MCP tool `llm`** com `generate`, `list_models`, `budget_status`, `proxy_status`.

**Aceitação dura**: ao final, deve ser possível rodar uma task autônoma de browser-use-harness apontando para o MCP-Graph Proxy, e cada chamada LLM aparece no `llm_call_ledger` com `caller=browser-use` e `cell_id` correlacionado ao node do experimento no graph.

## Arquitetura proposta

Dois módulos novos em `/Users/diegonogueira/mcp-graph-workflow/src/core/`:

```
src/core/llm/                          # camada SDK (camada 1)
  types.ts            # LlmRequest, LlmResponse, LlmUsage, ModelSpec
  errors.ts           # LlmAuthError, LlmRateLimitError, LlmBudgetExceededError, LlmTransportError, LlmContextWindowError, LlmModelUnknown
  registry.ts         # model→provider routing + tier ('cheap'|'mid'|'expensive') + pricing seed
  pricing.ts          # usage + ModelSpec → USD
  budget.ts           # BudgetLedger.record/aggregate/guard (per-cell, per-run)
  retry.ts            # withRetry (extraído de llm-client.ts atual)
  telemetry.ts        # hook de knowledge store (1 entrada por chamada)
  gateway.ts          # LlmGateway facade: generate(), listModels(), budgetStatus()
  adapters/
    base.ts           # ProviderAdapter interface
    anthropic.ts      # port de generateAnthropic
    openrouter.ts     # port de tools/h9v2-pilot/openrouter-client.ts
    openai.ts         # OpenAI nativo
    copilot.ts        # port de generateCopilot (preserva header editor-version)
    ollama.ts         # stub deferido (local OpenAI-compatible)
  index.ts

src/core/proxy/                        # MCP-Graph Proxy HTTP server (camada 2)
  server.ts           # HTTP server (Fastify ou node:http) bind 127.0.0.1:PORT
  routes/
    chat-completions.ts  # POST /v1/chat/completions  (suporta stream=false na v1; SSE deferido)
    models.ts            # GET  /v1/models           (lista filtrada por tier)
    health.ts            # GET  /healthz, GET /readyz
  auth.ts             # bearer token simples (gerado e gravado em ~/.mcp-graph/proxy.token)
  request-shape.ts    # OpenAI ChatCompletionRequest → LlmRequest (e response back)
  cors.ts             # CORS allow-list (browser-use precisa)
  metrics.ts          # contadores prometheus-style opcionais
  index.ts            # startProxy(opts) / stopProxy()
```

- A camada 2 usa **só** a camada 1 (`LlmGateway`). Toda chamada externa cai no mesmo ledger/budget guard que chamadas internas.
- Daemon ganha flag `--proxy-port` (default `4127`); se ausente, proxy não sobe.
- Default config: `allowExpensive: false` — bloqueia claude-sonnet/opus e gpt-4o/5 a menos que opt-in explícito.
- Identidade do caller no proxy: header `X-MCP-Graph-Caller` (ex: `browser-use`, `copilot-vscode`); ausente → `caller=external`.

## Schema (migration v65)

```sql
CREATE TABLE IF NOT EXISTS llm_call_ledger (
  id TEXT PRIMARY KEY,                -- ulid
  ts INTEGER NOT NULL,                -- unix ms
  project_id TEXT,
  cell_id TEXT,                       -- node id do grafo
  run_id TEXT,
  caller TEXT NOT NULL,               -- 'browser-harness' | 'delegate' | ...
  provider TEXT NOT NULL,
  model TEXT NOT NULL,
  input_tokens INTEGER,
  output_tokens INTEGER,
  cached_input_tokens INTEGER,
  cost_usd REAL NOT NULL,
  latency_ms INTEGER,
  status TEXT NOT NULL,               -- 'ok' | 'error'
  error_kind TEXT
);
CREATE INDEX idx_llm_ledger_cell ON llm_call_ledger(cell_id);
CREATE INDEX idx_llm_ledger_run  ON llm_call_ledger(run_id);
CREATE INDEX idx_llm_ledger_ts   ON llm_call_ledger(ts);
```

Mais `project_settings`: `llm.budget.cap_usd_per_run`, `llm.budget.cap_usd_per_cell` (default **1.00** = regra do usuário).

## Estratégia de testes (Vitest + TDD)

- **Adapter unit tests** (`tests/core/llm/adapters/*.test.ts`) — mock `fetch`, asserir shape de request, normalização de response, mapping de erros 401/429/5xx/timeout.
- **registry/pricing** — modelo desconhecido lança `LlmModelUnknown`; cálculo de custo vs valores golden; filtro cheap-only.
- **budget guard contract** — pre-flight bloqueia quando `current + estimated > cap`; ledger insert pós-call; concorrência serializada por SQLite.
- **gateway integration** — roteamento por model id, retry 5xx, `LlmBudgetExceededError` limpo, telemetria gravada.
- **Regression** — `tests/core/browser-harness/llm-client.test.ts` existente deve passar contra o shim. **Gate de no-regressão.**
- **Live smoke** (`it.skipIf(!process.env.OPENROUTER_LIVE)`) — uma chamada real openrouter/auto cheap, custo < $0.01.
- **MCP tool** — contract test `generate`/`list_models`/`budget_status`.

## Riscos & tradeoffs

- **Streaming deferido para v2** — `LlmResponse` já com discriminant opcional, evita breaking change futuro.
- **Tool/function-calling**: v1 só passthrough via `providerExtras`. Self-heal não precisa hoje.
- **Budget atomicity**: SQLite serializa writes — múltiplos agentes concorrentes podem estourar cap em 1 chamada. Documentar.
- **Pricing drift**: `registry.ts` é data-only; TODO adicionar `scripts/sync-openrouter-prices.mjs` (fora do escopo v12).
- **Copilot header**: preservar `editor-version: mcp-graph/1` exatamente como hoje, ou auth do self-heal regride.
- **Streaming no proxy**: clientes como browser-use e Copilot esperam SSE. v1 do proxy responde non-streaming; v12.1 adiciona SSE. Mitigação: documentar limitação e validar que browser-use funciona em modo non-stream.
- **Bind local-only**: proxy em `127.0.0.1`, nunca `0.0.0.0`. Token bearer obrigatório. Sem token = 401. Documentar em SECURITY.md.
- **Mapping OpenAI→provider**: alguns campos OpenAI (logit_bias, n, seed) não têm equivalente Anthropic — passar via `providerExtras` quando rotear pra Anthropic, ou retornar 422 com mensagem clara.
- **Concorrência no proxy**: Fastify lida bem; budget guard ainda é o ponto de serialização (igual ao SDK).
